# 中文学术表达规则

默认采用计算机科学与技术专业硕士学位论文的正式中文。目标是专业、准确、自然且信息密度适当，不追求装饰性词汇，也不以压缩为由删除复现所需细节。

## 0. Markdown 正文格式

- 可直接用于论文的正文默认以 Markdown 输出。使用 `#`、`##`、`###` 等标题层级表达论文结构，标题级别应与用户提供的目录一致；标题语法属于结构标记，不用于句内强调。
- 正文段落保持普通文本，不使用 `**...**`、`__...__` 等加粗语法，不使用 `<mark>`、HTML 样式、颜色或其他高亮方式，也不使用斜体作为一般性强调。
- 不使用提示框、引用框充当强调框，不加入表情符号、图标、装饰性分隔线、徽章或面向网页阅读的视觉组件。
- 只有内容本身需要枚举、对照或结构化呈现时才使用列表和表格；普通论述不拆成大量项目符号。公式继续遵循术语与符号表中的 Markdown/Word 兼容规范。
- 代码标识、命令或文件名确需出现时可使用行内代码格式；不得用行内代码格式强调普通论文术语。论文正文原则上不使用代码围栏，除非章节确实需要展示程序或算法代码。
- 强调研究重点时依靠明确主语、逻辑顺序、定量证据和段落位置，不依靠视觉加粗或高亮。用户另有学校模板或排版要求时，以正式模板为准。
- 上述限制针对论文正文、摘要、图表说明和可直接粘贴的章节内容。用户要求问题分析、审查报告或修改建议时，可以使用必要的列表组织问题，但不要把分析性格式混入交付的正文。

## 1. 保留研究事实

- 润色优先保持原意、技术含义、证据强度和数值口径。语句更流畅不能成为改变模型机制或实验结论的理由。
- 用户表述与代码、数据或术语表冲突时，先指出冲突并给出修改建议；不静默“修正”为未经确认的新事实。
- 强结论使用与证据匹配的动词：代码“实现/采用”，实验“显示/表明”，统计关联“相关”，机制推断“提示/可能与……有关”。谨慎使用“证明”“揭示机制”“普遍适用”。

## 2. 信息密度与段落组织

- 每个段落围绕一个清晰功能展开，但不强制所有段落套用同一三段式或句式。
- 开头直接进入研究对象、技术问题、方法关系或实验发现。删除不承载具体信息的背景铺陈。
- 理论分析可适当展开推导和概念边界；方法写足输入输出、计算关系与训练协议；实验以数据、比较关系和不确定性为中心。
- 句长自然变化。一个长句包含多个独立判断、多个转折或容易产生修饰歧义时拆分；短句不应连续堆叠成说明书。
- 小节末尾只有在需要归纳发现、建立章节过渡或回应研究问题时才总结，不机械添加“本节小结”。

## 3. 减少模板化表达

优先删改不能回答“具体是什么、依据是什么、产生何种影响”的表达，例如：

- “随着科学技术的快速发展……”
- “具有十分重要的理论意义和现实意义……”
- “为相关领域的发展奠定了坚实基础……”
- “取得了良好的实验效果……”
- “提供了新的思路/有力支撑/宝贵见解……”

这些短语不是机械禁用；只有在后文立即给出明确对象、证据和实际含义时才保留。用具体问题、结果或限制替代笼统评价。

避免以下机械模式：

- 每段以“首先、其次、再次、最后”排列，但内容并非真实步骤或层次；
- 每句都以“此外、同时、值得注意的是、综上所述”开头；
- 为节奏反复制造三项并列、对称句或“不仅……而且……”；
- 在同一段用“有效、优越、鲁棒、先进”等多个形容词重复评价；
- 每节都重复研究意义、方法优势和相同结论；
- 从英文逐词翻译形成过长“的”字链或抽象名词链。

连接词只在逻辑关系需要显式标示时使用。更自然的衔接通常来自共同主语、因果对象、比较对象或上一句提出的限制。

## 4. 中文句法与用词

- 优先使用明确主语和直接动词，如“模型将……映射为……”“实验采用……划分”“R² 随样本量增加而上升”。
- 减少无必要的“进行了……的研究”“实现了对……的预测”“能够有效地……”；可改为“研究……”“预测……”“在……指标上提高……”。
- 被动结构用于突出过程或结果时可以保留，但不要连续使用“被……所……”。
- 同一概念使用固定术语。技术术语的必要重复优于为了文采替换成不精确近义词。
- 术语统一使用“宽通道/深通道/双通道”“距离相关性独立筛选”和“DynaGS 模型”，不使用“宽通路/深通路/双通路”“距离相关性确定性独立筛选”或“DynaGS 框架”。英文术语首次出现采用“中文全称（英文全称，缩写）”，DC-SIS 首次出现使用完整中英文及缩写，后文只用 DC-SIS。
- 避免行政报告式、宣传式或新闻式语气；不使用“国际领先”“填补空白”等无法严格证明的表述。
- 中文标点遵循论文规范；英文缩写、变量和数值与中文之间的空格按学校模板统一，不在同一稿件混用多套格式。

## 5. 定量与比较表达

- 同时交代比较对象、数据条件、指标、方向和幅度。例：“在相同测试划分下，DynaGS 模型的 PCC 比基线 A 提高 0.03”，而非“性能明显更好”。
- 区分百分点变化与相对百分比变化；不得根据绝对差自行改写成“提升 x%”。
- 小数位数应与实验稳定性和原始结果一致，不擅自增加精度。
- 均值后注明变异性类型和重复单位，如“5 折均值±标准差”；不要把折间波动写成样本置信区间。
- “显著”仅用于统计检验或明确定义的实际阈值。没有检验时使用“提高”“下降”“差异为”等描述性表达。
- 负 R²、无效 PCC 时间点、异常波动或基线不公平不能通过只报有利均值来隐藏。

## 6. 公式附近的表达

- 公式前说明它解决的计算问题，公式后定义每个新变量及维度，再解释其与模型模块的关系。
- 不把代码逐行翻译成正文；提炼数学运算，但保留影响输出的归一化、广播、聚合和门控关系。
- 公式与叙述的主语一致。例如公式是“宽通道输出加门控深通道输出”，正文不能写成“两通道加权平均”。
- 避免为显得复杂而引入无用途的符号、矩阵字体或重复公式。
- 数学形状统一使用普通 `R`（如 `R^{B\times M}`），不使用双线实数域符号；预测值统一使用 `\hat{}`，不使用 `\widehat{}`。

## 7. 修改已有文字

按以下顺序处理：事实与术语错误、论证与章节功能、句间衔接、冗余、语法和标点。若用户要求轻度润色，不随意重排论证或加入新结论；若原文存在技术错误，明确指出而不是只做表面润色。

用户要求“直接修改”时，默认返回完整清洁稿。只有关键证据缺失、原意存在两种实质解释或修改会改变研究结论时，才在正文后附简短待确认项。

## 8. 英文学术写作补充

用户明确要求英文或期刊稿时，保持同样的事实、术语和证据约束。使用直接的科学英语，避免长名词串和宣传性形容词；完成的方法和结果通常用过去时，公认知识及图表内容可用现在时。翻译以含义和学科语域为单位，不逐句照搬中文结构。

“自然写作”不意味着故意加入口语、语法错误或无意义变化，也不采用规避 AI 检测的特殊技巧。
